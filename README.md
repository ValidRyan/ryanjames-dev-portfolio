### About

This project began as a simple educational application concept and steadily developed into a suite of tools for streamlining creative work and everyday computer operations.

The original education application did not progress beyond ideation. Its central concern—making computing easier to understand and operate—continued into four working prototypes. Each approaches computer literacy, accessibility, and common operating-system friction from a different direction.

**Outcome:** A working prototype that fulfilled its schematic by repurposing and repackaging the processing between input and output for different use cases.  
**Highlights:** Portable file-processing pipeline · Input–process–output model · Reusable transformation logic

**Outcome:** A working prototype that fulfilled its schematic by treating files and folders as operators, connecting them before allowing processes to run between them.

### How I Work

- **System Design & Architecture** — I develop systems from first principles, define their constraints, and trace how information moves from input through processing to output.
- **Custom Systems Mapping** — I use detailed diagrams to expose structure, dependencies, interaction paths, and opportunities that are easy to miss in conventional documentation.
- **AI as a Force Multiplier** — I use advanced prompting and multi-step AI workflows to accelerate exploration, implementation, testing, and documentation while retaining architectural ownership.
- **Troubleshooting & Ingenuity** — I isolate problems systematically, challenge assumptions early, and turn abstract schematics into testable prototypes.

---

### Technical Approach

I begin with the problem and the system boundary, then reduce the design to a small set of explicit relationships, constraints, and operations. From there, I use AI deliberately to explore alternatives, generate scaffolding, stress-test decisions, and accelerate iteration.

The four prototypes share a consistent architectural thread: files and folders are treated as meaningful parts of a processing system rather than passive storage. Position and context determine their role; processing remains user-directed; and each interface aims to make the system's behaviour easier to see, understand, and control.

The result is a documented progression from computer-literacy research to practical prototypes, with the implementation used to test whether each schematic works as intended.
